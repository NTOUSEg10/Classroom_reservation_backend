# Iteration 2 功能與驗收紀錄

2026-11-17 · 海大教室借用平台

本次展示從學校 Google 帳號登入與首次建檔開始，接著由借用人查詢、申請或取消，最後由管理員審核、管理借用資格與記錄鑰匙交還。各功能的實作入口和驗收結果如下。

| 工作卡                    | 操作入口                             | 可驗收的結果                                                                   |
| ------------------------- | ------------------------------------ | ------------------------------------------------------------------------------ |
| U1 註冊帳號／登入系統     | 登入／註冊                           | 使用 `@email.ntou.edu.tw` 的學校 Google 帳號登入。首次登入導向帳戶建檔。       |
| U1 填寫基本資料及聯絡資訊 | 帳戶 → 完成基本資料                  | 填寫姓名、證號、聯絡電話與系所後建立借用人資料。信箱來自已驗證的 Google 身分。 |
| U2 條件篩選               | 查詢教室                             | 設定日期、起迄時間、系館、容納人數與設備，查看符合條件的教室和可用狀態。       |
| U3 送出預約借用申請       | 教室詳情 → 預約借用                  | 選定未來時段並填寫用途、人數後，新增「申請中」紀錄。                           |
| U3 送出即時借用申請       | 教室詳情 → 即時借用                  | 帶入接近目前時間的時段，送出後由管理員審核。                                   |
| U3 取消申請               | 我的借用 → 取消借用                  | 本人可在規則允許時取消自己的申請，狀態改為「已取消」。                         |
| U4 查看借用紀錄、審核進度 | 我的借用、通知中心                   | 查看本人的紀錄和狀態。審核結果更新後，可從借用紀錄或通知確認。                 |
| U7 查看借用申請           | 管理台 → 待審申請／借用紀錄          | 管理員可查看申請人、教室、時段、人數、用途與狀態，以及依狀態篩選借用紀錄。     |
| U7 核准或駁回借用請求     | 管理台 → 待審申請                    | 逐筆核准或拒絕。拒絕須填寫原因，同教室重疊時段只能核准一筆。                   |
| U8 檢視借用人清單         | 管理台 → 使用者                      | 列出使用者的角色、身分驗證及帳號狀態，支援分頁。                               |
| U8 修改借用人狀態         | 管理台 → 使用者 → 停權帳號／恢復帳號 | 停權後即使借用人仍登入，也會被阻擋送出新申請。恢復後，符合資格者可再申請。     |
| U9 更新鑰匙借用狀態       | 管理台 → 借用紀錄                    | 對已核准的借用操作交付鑰匙及記錄歸還，保存兩個時間點，歸還後留在借用歷史。     |

## 本次程式修正

同一借用人對同一間教室已有時間重疊的申請中、已核准或已交付鑰匙紀錄時，再送一筆會收到 HTTP 409，並提示到「我的借用」查看。檢查和寫入放在同一筆交易內，並沿用借用人的資料列鎖。不同借用人的待審申請仍可競爭同一時段，核准時由資料庫約束確保只有一筆占用。取消原申請後可重新送出，起迄相接也可分別申請。 [實作](../app/main.py) · [規格](SPEC.md)

## 驗收證據

- 學校 Google 登入、首次建檔與第一位管理員已在真實 Supabase 驗證。證號保存於平台資料，校園身分由已驗證的學校 Google 信箱確認。 [串接與驗收紀錄](CONNECT_REAL_SUPABASE.md)
- 整合測試涵蓋查詢篩選、兩種申請、本人歷史與取消、拒絕理由、管理員權限、停權與恢復，以及鑰匙交付和歸還。新增回歸測試讓同一人同時送出兩筆，驗證只建立一筆。 [API 整合測試](../tests/test_api.py)
- 併發測試模擬 100 位借用人申請同教室同時段，再同時核准，驗證只有一筆核准成功。 [併發測試](../tests/test_concurrency.py)
- 鑰匙借還影片使用隔離的本機測試庫與示範帳號。錄影完成後關閉測試站並移除該次測試資料庫。校方正式教室清單與課表仍待提供。
- 本機回歸測試共通過 274 項後端測試及 46 項前端測試。各版本的自動驗證可從 GitHub Actions 查看。 [後端 Actions](https://github.com/NTOUSEg10/Classroom_reservation_backend/actions) · [前端 Actions](https://github.com/NTOUSEg10/Classroom_reservation_frontend/actions)
